## 先找症状：你遇到的是哪一种断线？

| 现象 | 先核对什么 | 下一步 |
| --- | --- | --- |
| 解锁后第一次加载失败，等一下恢复 | 恢复耗时、目标应用是否重新发起请求 | 做锁屏前后对照，记录能否自动恢复 |
| 必须先点开客户端才恢复 | 客户端状态、系统电池限制、连接日志 | 分安卓和 iPhone 检查，暂不同时换节点 |
| Wi-Fi 正常，蜂窝网络始终失败 | 客户端与目标应用的联网权限、节点入口适配 | 固定节点，分别测试两种网络 |
| 两种网络单独能用，切换时失败 | 自动重连、规则和网络切换后的连接状态 | 做双向切网测试，记录恢复方法 |
| VPN 图标存在，只有某个 App 不通 | 应用权限、分应用代理、规则、账号与平台状态 | 对照另一个任务，避免只看图标 |
| 手机明显耗电，但访问一直正常 | 屏幕、实际流量、信号、后台任务和统计时段 | 单独做耗电对照，不把掉电当作断线证据 |
| 多设备、多个常用节点都反复失败 | 订阅、公告、本地网络和服务端异常 | 排除共同因素后，再比较替代机场 |

如果主要问题是“同一台设备，家宽慢、热点快”，可搭配[电信、联通、移动三网机场选择教程](/article/vpn-airport-telecom-unicom-mobile-guide-2026/)检查接入网络。本文重点解决手机锁屏、应用恢复和切网时的行为，两种测试不要混为一项。

## 一、先分清机场、客户端、VPN图标与实际联网

“机场 VPN”是常见搜索叫法。多数翻墙机场提供代理节点和订阅，手机客户端读取配置，再按规则处理请求。安装客户端、订阅有效、系统显示 VPN、目标应用能完成任务，是不同层面的状态。

| 概念 | 能说明什么 | 还不能证明什么 |
| --- | --- | --- |
| 机场账号和订阅 | 你获得了某项服务的配置与使用额度 | 当前节点一定可用、所有协议都兼容 |
| 客户端界面 | 应用展示了配置或连接状态 | 锁屏前后状态没有变化、目标流量一定经过代理 |
| 系统 VPN 状态 | 系统报告的 VPN 连接情况 | 每个 App、域名和媒体连接都能成功 |
| 节点延迟数字 | 指定检测目标在当时有响应 | 实际网站、视频、消息或上传任务一定成功 |
| 实际任务结果 | 该任务在所记录条件下完成或失败 | 未测试时段也正常、未来不会中断 |

Android 的[官方 VPN 文档](https://developer.android.com/develop/connectivity/vpn)区分系统 VPN 服务、网关连接和分应用处理。因此，状态图标应和实际请求一起看。需要补齐基础概念时，可先读[翻墙机场、节点、订阅与客户端入门教程](/article/what-is-vpn-airport-beginner-guide-2026/)。

**解锁后看到页面停在旧内容，不能证明锁屏期间隧道已经断开。** 页面可能没有刷新，应用任务也可能暂停。排查时应发起一个新的、可重复的请求，并观察恢复行为；只有图标或一次旧页面截图，证据还不够。

## 二、动设置前，建立一个可复现的手机测试

先保存当前配置，记录下面几项，避免改完后无法回退：

```text
手机型号、系统版本：
客户端名称、版本、下载来源：
当前机场与节点、协议、倍率：
网络：Wi-Fi / 蜂窝网络，运营商与信号情况：
低电量或省电模式、客户端电池设置：
目标任务、失败现象、发生时间：
手动点开客户端或重连后是否恢复：
```

不要把订阅令牌、账号密码和完整订阅链接放进公开记录。配置备份方法可参考[机场订阅链接安全指南](/article/airport-subscription-security-guide-2026/)；首次导入订阅则看[Clash 与 Shadowrocket 订阅使用教程](/article/airport-subscription-clash-shadowrocket-guide-2026/)。

### 第一步：确认亮屏基线能成功

固定一个节点和一种网络，用同一个目标应用完成一次实际任务，例如刷新页面并打开一篇新内容。另选一个在当前网络中本来就能直接访问的服务，检查本地联网是否正常。

如果亮屏时已经失败，先排查账号额度、节点、规则和订阅兼容。此时还无法把问题归因于锁屏或后台限制。

### 第二步：普通锁屏，解锁后先测目标应用

锁屏约 3 分钟，再解锁，**先打开目标应用发起新请求，不要先进入 VPN 客户端**。记录请求是否成功、多久恢复、是否需要手动重连，再检查客户端状态和对应时间的日志。

这样可以避免“先点开客户端”改变了恢复过程，却没有记下来。将同一操作重复几次；如果日常问题只在半小时后出现，再补做相应时长的测试。没有覆盖长时间待机，就写“尚未验证”。

### 第三步：把手动强退与普通锁屏分开测

从最近任务中划掉客户端、系统设置中的“强行停止”、普通切到后台和锁屏，不是相同操作；不同平台、客户端的处理也可能不同。

首先测试日常不主动干预客户端时的表现。若要检查强退后的行为，单独记录操作与结果，不要据此直接声称“所有锁屏都会断”。

### 第四步：一次只改变一个条件

例如保持节点和网络相同，只对照客户端某一项电池设置；或保持设置相同，只换同服务的另一节点。不要同时换机场、协议、DNS 和系统电池模式，否则即使恢复，也难以知道哪个变化起作用。

## 三、安卓手机：查后台设置，也查VPN服务是否被替换

### 1. 查看电池用量和当前限制

先在系统设置搜索“电池用量”或“应用电池用量”，找到当前客户端，记录其后台使用设置及统计时间范围。Google 的 [Pixel 耗电排查说明](https://support.google.com/pixelphone/answer/6090599?hl=zh-Hans)提供了“设置 → 电池 → 电池用量”等入口，并建议默认保留电池优化。

小米、OPPO、vivo、荣耀、三星等设备的菜单和限制机制可能不同，不要把 Pixel 的名称当成所有安卓手机的固定路径。应结合设备厂商和客户端当前说明操作。

如果客户端官方文档明确要求某项后台设置，而你的设备限制了它，可先保存原值，**仅对该客户端做一次受控调整，再重复锁屏测试**。没有改善就恢复原值。无需为了排查而关闭全部应用的省电功能，也不要仅凭一次恢复就认定调整能长期解决问题。

### 2. 检查“始终开启VPN”是否适用

[Android 帮助文档](https://support.google.com/android/answer/9089766?hl=zh-Hans)介绍了系统 VPN 设置；找不到菜单时可在设置里搜索“VPN”。是否提供“始终开启”等选项，还要看系统、设备策略和客户端支持，选项不可用时不要套用其他手机的截图。

“始终开启”关注服务的持续运行，**不能保证远端节点始终可达**。若同时启用了“阻止不使用 VPN 的连接”，隧道未建立时无法联网可能正是所选策略的表现。不要把取消阻断后恢复直连，记录成“机场断线已修复”。有关这些功能的区别，可参考[Android 企业 VPN 配置说明](https://support.google.com/work/android/answer/9213914?hl=en)。

### 3. 检查其他网络工具是否占用了VPN服务

有些去广告、防火墙或网络工具会使用本地 VPN 方式工作。Android 官方说明，同一用户或工作资料同时只有一个活动 VPN 服务，启动新的服务会停止原服务。[来源：Android VPN 服务机制](https://developer.android.com/develop/connectivity/vpn)

因此，出现“打开另一个网络工具后机场断开”时，应先核对它们的实现方式及共存说明。个人资料与工作资料也要区分；受单位管理的配置应交由管理员处理，不要直接删除。

### 4. Wi-Fi能用，流量不能用时看联网权限

核对目标应用和客户端是否允许使用蜂窝数据，是否存在数据节省或厂商单独的联网限制。然后在相同节点下，分别用 Wi-Fi 与蜂窝网络完成同一任务。

只在蜂窝网络持续失败时，再检查运营商接入、节点入口及服务方支持说明。单纯反复放宽电池设置，无法验证网络入口问题。

## 四、iPhone：别把低电量模式和VPN断开画等号

### 1. 记录低电量模式，按相同条件对照

Apple 的[低电量模式说明](https://support.apple.com/en-us/101604)列出了后台 App 刷新等受影响功能。**该说明不能直接推出“开启低电量模式必然关闭所有 VPN”**，也不能据此保证关闭它就能解决某个客户端的问题。

可以在“设置 → 电池”查找对应选项；部分机型或版本会在“电量模式”中提供设置。记录原状态，在相同网络、节点和锁屏时长下做对照。若低电量模式是你日常必须使用的条件，也应在该条件下验收候选，而非只在关闭后判断好用。

### 2. 先看系统连接和实际请求，再检查客户端

解锁后先做目标任务，再在系统设置中搜索“VPN”核对当前启用配置，最后查看客户端是否有断开或重连记录。客户端界面是否一直停留在前台，不应作为唯一判断依据。

如果使用按需连接或自动连接规则，按照客户端官方说明核对启用条件，记录自己是否修改过它们。不确定某个开关含义时，先保存配置，不要把所有高级选项一起打开。

### 3. 区分目标应用权限、消息推送与代理连接

只有某个应用在蜂窝网络不可用时，检查其蜂窝数据权限、账号与服务状态；只有消息提醒延迟时，再检查该应用的通知设置和实际消息获取情况。**“未收到通知”和“所有新请求失败”需要分别记录。**

涉及 Shadowrocket 订阅导入、配置或 DNS 的问题，可接着看[Shadowrocket 使用教程](/article/Shadowrocket/)和[小火箭故障排查专题](/shadowrocket/)。不要为排查个人订阅删除单位设备管理配置。

## 五、Wi-Fi切换手机流量后失效，怎么测才公平？

先确认两种网络单独都能完成目标任务，再观察切换过程。否则“切网失败”也可能只是其中一种网络原本就不可用。

1. 固定节点、客户端规则和目标任务，在 Wi-Fi 下验证一次。
2. 暂停正式会议、上传等不能中断的工作，在测试中关闭 Wi-Fi，确认手机已使用蜂窝网络。
3. 在目标应用发起新请求，记录恢复耗时、是否手动重连及具体报错。
4. 回到 Wi-Fi，重复一次，分别填写两个方向。
5. 如有必要，换一个节点复测；比较另一机场时，尽量使用相同地点、时段和手机设置。

网络切换时，已有任务如何恢复取决于协议、客户端和应用实现。新页面能打开，也不等于原来的上传或通话能无缝继续；应把**新请求成功**与**原任务恢复**分开记录，不用“零秒切换”作为所有用途的统一要求。

需要长期移动使用时，还应覆盖自己常见地点。室内信号弱或接入网络变化的结果，应与固定位置的对照测试分开，不能全归因于机场。

## 六、开机场VPN耗电快，怎样判断原因？

先看实际工作量与系统统计，不凭体感给某个协议排省电名次。看视频、屏幕常亮、后台同步、信号状况、诊断任务以及重复连接，都可以作为需要控制的变量；哪些因素影响了你的手机，需要对照结果支持。

### 先查看正确的统计范围

安卓可查看系统电池用量；iPhone 可按 Apple 的[电池用量说明](https://support.apple.com/zh-cn/102432)进入“设置 → 电池”，选择相应时段和应用记录。菜单与统计界面可能随版本变化。

不要把某应用在所选时段的耗电占比，直接当成手机掉电的百分点；也不要拿整天使用记录解释刚刚几分钟的操作。记录测试前后电量、时长、任务和充电状态，才便于比较。

### 做两组相同任务的观察

选择相近的起始电量、相同屏幕亮度、网络、地点、任务与时长，测试期间不充电。可以先各观察约 30 分钟，固定非必要测速与日志设置，再在条件相近的另一个时段重复；这是个人粗略排查，不是实验室能耗测量。

- **同一订阅比较设置：**只改变一个有官方说明的选项，检查恢复与耗电是否一起变化。
- **同一任务比较节点或候选：**保持客户端和设备条件相同；有兼容差异时明确标注，避免比较失去依据。
- **观察无需代理的任务：**仅在可直接访问且符合你的隐私与单位要求时，记录不经过代理的基线；任务本身不同，就不能直接相减归因。

例如，假设一次观察从 80% 变为 77%，耗时 30 分钟，其观察速率为 `3个百分点 ÷ 0.5小时 = 6个百分点/小时`。**这是假设算例，不能据此预测全天续航，也不能把全部掉电都归给 VPN。** 短时电量取整和任务波动会影响比较，小幅差异尤其需要重复观察。

若反复重连与耗电同时出现，先记录日志时间是否对应，再排查失败原因。不要为了“保活”盲目缩短检测间隔、频繁跑满速测速，或降低加密与安全设置。

## 七、可复制的手机机场验收表

先写自己的需求，例如“日常锁屏后能自动恢复网页”“切到流量后不必手动重连”。通过条件取决于真实用途，下面不设置统一的合格秒数或耗电标准。

| 验收项目 | 当前服务 / 候选 A | 候选 B | 我的要求 |
| --- | --- | --- | --- |
| 手机、系统、客户端及配置版本 | 待填 | 待填 | 条件可复现 |
| 节点、网络、时间与省电设置 | 待填 | 待填 | 相同变量尽量固定 |
| 亮屏时新请求 | 待填 | 待填 | 常用任务可完成 |
| 普通锁屏后新请求与恢复时间 | 待填 | 待填 | 按日常可接受等待时间 |
| 较长待机后恢复 | 待填 | 待填 | 未测则填“未验证” |
| Wi-Fi → 蜂窝网络 | 待填 | 待填 | 记录自动或手动恢复 |
| 蜂窝网络 → Wi-Fi | 待填 | 待填 | 与反方向分别记录 |
| 原有上传、音频等任务恢复 | 待填 | 待填 | 按实际任务要求 |
| 电池观察时长、工作量与掉电 | 待填 | 待填 | 不把占比当掉电百分点 |
| 另一工作时段复测 | 待填 | 待填 | 不只保留一次成功 |

失败记录可用这一行：`时间｜网络｜节点｜操作｜首次请求结果｜恢复用时｜是否打开客户端｜日志摘要｜下一步`。保留失败样本，并遮住令牌和私人信息，比只保存一张绿色延迟截图更有帮助。

## 八、什么时候该换设置、节点或机场？

| 对照结果 | 更值得先做的事 |
| --- | --- |
| 不同机场在同一手机上都只有锁屏后失败 | 优先检查共同的系统与客户端条件，保留日志 |
| 某个节点失败，同服务另一节点正常 | 先换已验证节点，向服务方报告原节点 |
| 单一目标 App 失败，其他任务正常 | 先查应用、规则、账号与目标平台 |

## 九、常见问题

### 手机上有VPN图标，为什么还是打不开网页？

图标不能替代实际任务测试。检查目标应用是否经过预期路径、规则与 DNS 是否正确、节点是否可达，以及目标平台和账号是否正常。解锁后先发起新请求，再看连接日志。

### 安卓手机要不要关闭所有电池优化？

不建议。先查看系统和客户端官方说明，只对已发现的问题做单项对照，记录原设置和结果。没有改善时恢复，避免扩大调整范围却没有增加证据。

### iPhone开低电量模式就一定会断开机场吗？

不能这样判断。Apple 说明了低电量模式会限制一些后台功能，但具体客户端是否中断仍需在同一网络、节点与锁屏条件下验证。后台刷新开关与 VPN 实际连通不能画等号。

### 换更贵的专线机场，就能解决手机锁屏断线吗？

不能保证。系统限制、客户端行为、配置冲突和目标应用问题，需要先定位。线路和服务差异只有在设备、配置与任务条件相近时，才便于通过对照评估。

### 哪一种机场协议最省电？

没有本文可支持的统一名次。设备、实现、流量和网络条件都会影响观察；应使用相同任务、时长和网络比较，并同时记录连接恢复表现，不能只看一次电量变化。

### 手机推送延迟，就是机场断线吗？

不一定。通知设置、目标应用状态与联网情况需要分别核对。先确认应用打开后能否完成新请求，再记录通知是否到达，避免把两种现象合并成一个结论。
